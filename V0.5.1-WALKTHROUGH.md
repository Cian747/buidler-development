# v0.5.1 implementation walkthrough

## Before touching files
1. In GitHub Desktop, commit the verified v0.4.0 source as `baseline: verified v0.4.0`.
2. Create a branch named `feature/shared-global-design-system`.
3. Export the Local database and copy the current plugin folder.

## Files introduced or changed

### New
- `includes/class-ib-global-styles.php`: shared defaults, validation, REST endpoints and CSS token generation.

### Updated
- `independent-builder.php`: version 0.5.1 and loads the new class.
- `includes/class-ib-plugin.php`: creates the service, localizes its endpoint/defaults/permissions, and loads shared frontend CSS on builder pages.
- `includes/class-ib-renderer.php`: preserves v0.4 page-level styles as a fallback while the shared design system has not yet been saved.
- `includes/class-ib-rest.php`: permits only a whitelist of spacing token references in node dimensions.
- `assets/js/editor.js`: loads global settings separately from page content, offers controls and saves settings to the site-level endpoint.
- `assets/css/editor.css`: styles the new settings panel and uses tokens in the preview.
- `assets/css/frontend.css`: provides scoped token-aware styles and safe defaults.

## Install by replacing files in your existing plugin folder
1. Deactivate Independent Builder in WordPress.
2. Copy `includes/class-ib-global-styles.php` from this release into your existing `includes` folder.
3. Replace the other listed files with their v0.5.1 versions.
4. Confirm the folder structure is unchanged and the plugin entry point remains `independent-builder.php`.
5. Reactivate the plugin and confirm that its version is 0.5.1.

Alternatively, replace the full plugin directory with the `independent-builder` folder in this package after preserving the previous folder as a backup.

## First save
1. Open a builder-managed page.
2. Click an empty area of the canvas to deselect elements.
3. The Settings panel should show `Site-wide design system`.
4. Adjust a colour or typography value.
5. Click `Save site design system`.
6. The WordPress option `ib_global_design_system` is created/updated with autoload disabled; the settings are fetched only when a builder-managed page needs them.

## Confirm storage
WP-CLI:
```bash
wp option get ib_global_design_system --format=json
```

Adminer SQL (replace `wp_` with the actual table prefix):
```sql
SELECT option_name, option_value
FROM wp_options
WHERE option_name = 'ib_global_design_system';
```

## REST API
- GET `/wp-json/independent-builder/v1/global-styles` — requires `edit_pages`.
- POST `/wp-json/independent-builder/v1/global-styles` — requires `manage_options`; JSON body contains a `settings` object.

## Compatibility notes
- v0.4 page-level `settings.globalStyles` are not deleted.
- If the shared option does not exist, the renderer continues to use the old page-level values.
- When opening a v0.4 page before a shared system has been saved, the editor loads its legacy values as a suggestion. An administrator can choose Save to make those values site-wide.
- Explicit per-element styling continues to take precedence over global typography and colours. Clear an element's local style value if it should inherit a global token. After removing legacy page-level global settings, click Save page as well as Save site design system.
- Global font choices are system fonts only. No remote Google Fonts or font downloads are included.

## Acceptance tests
1. Save the global design system and confirm the status reads `Site design system saved`.
2. Open a second builder page and confirm the same settings load.
3. Change primary colour; confirm buttons using the global primary token reflect it on both builder pages.
4. Change body and heading font families/sizes; confirm elements without explicit local overrides inherit them.
5. Confirm ordinary non-builder pages are not restyled.
6. Confirm older v0.4 pages still render; explicit local styles should remain intact.
7. Confirm a non-administrator with `edit_pages` can read settings but cannot save them.
8. Confirm malformed colours, font families, dimensions and shadows are rejected and defaults are retained.
